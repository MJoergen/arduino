HUB75 32×16 Panel Wiring

The DFRobot “RGB LED Matrix Panel 32×16, 512 LEDs, 6 mm pitch” is a generic HUB75 panel: sixteen signal pins, a separate 5 V feed, and no intelligence of its own. Everything below is what it takes to drive one from an Arduino.

  • Pixels 32 × 16
  • Pitch 6 mm
  • Active area 192 × 96 mm
  • Scan 1/8
  • Interface HUB75, 5 V logic
  • LEDs 512 RGB
01

Find the input header

Turn the panel over. There are two 2×8 IDC headers, usually silkscreened JIN1 and JOUT1, with an arrow between them showing the direction data travels. Use the input one — feeding the output header gets you nothing at all. The separate two-pin (or spade / Molex) connector is power, and it is not optional.

  • Colour data
  • Row address
  • Control
  • Ground
  • Unused on this panel
02

Power it separately

Do this before anything else Give the panel its own 5 V supply rated 2 A or more, and tie its ground to the Arduino’s ground. Powering the panel from the Arduino’s 5 V pin or from USB will brown out the board — the failure looks like flicker, random resets, or a sketch that never starts.

At full white every one of the 512 pixels is on, and a panel this size draws around 2 A. Ordinary content — text, sprites, a clock face — sits nearer 0.3–0.5 A. Size the supply for the worst case anyway; a supply that sags takes the logic levels with it.

03

Wire it to the Arduino

Adafruit’s RGBmatrixPanel library refreshes the panel by writing whole AVR ports at once, so the six colour pins are fixed by the library and cannot be moved. The address and control pins are arguments to the constructor, but keeping the canonical assignment below means every example sketch compiles as-is.

Panel pin Signal Uno pin What it does
1, 2, 3 R1 G1 B1 2, 3, 4 Colour bits for the upper half, rows 0–7. Fixed port pins.
5, 6, 7 R2 G2 B2 5, 6, 7 Colour bits for the lower half, rows 8–15. Fixed port pins.
9, 10, 11 A, B, C A0, A1, A2 Selects which of the eight row pairs is lit right now.
12 D — Fourth address bit. Unused on a 16-row panel; leave it open.
13 CLK 8 Shifts each colour bit into the panel’s shift registers.
14 LAT A3 Latches a finished row. Sometimes silkscreened STB.
15 OE 9 Output enable, active low — also how brightness is dimmed.
4, 8, 16 GND GND At least one. Without a common ground nothing has a reference.

Twelve wires plus a ground. If your panel came with the usual 16-way ribbon, cutting one end off and crimping individual DuPont sockets is easier to get right than counting through an IDC connector.

04

The first sketch

Install Adafruit RGB Matrix Panel and Adafruit GFX from the Library Manager. The seven-argument constructor is the 16-row form; the eight-argument one (with a D pin) is for 32-row panels. 

#include <Adafruit_GFX.h>
#include <RGBmatrixPanel.h>

#define CLK  8   // pin 11 on a Mega 2560
#define LAT  A3
#define OE   9
#define A    A0
#define B    A1
#define C    A2

// 7 arguments = 16 rows. false = single-buffered.
RGBmatrixPanel matrix(A, B, C, CLK, LAT, OE, false);

void setup() {
  matrix.begin();

  matrix.fillScreen(0);
  matrix.drawRect(0, 0, 32, 16, matrix.Color333(0, 0, 7));   // blue border
  matrix.fillCircle(16, 8, 4, matrix.Color333(7, 0, 0));     // red dot

  matrix.setTextColor(matrix.Color333(0, 7, 0));
  matrix.setCursor(2, 4);
  matrix.print("Hi");
}

void loop() {
  // Nothing here: a timer interrupt refreshes the panel by itself.
}

Every Adafruit_GFX call works — drawLine, drawBitmap, setTextSize, and scrolling by redrawing at a shifting x. Colours come from Color333(r, g, b) with 0–7 per channel, or Color444 / Color888; the driver runs four bits per channel underneath.

Two things that will bite you on an Uno

  • Timer1 belongs to the library. An interrupt refreshes all sixteen rows continuously in the background, so anything else wanting Timer1 — TimerOne, some PWM libraries, tone() on certain pins — will fight it and show up as flicker.
  • The framebuffer is 768 bytes of the Uno’s 2 KB of SRAM. Passing true for double-buffering doubles that to 1536 and leaves almost nothing for your own code; if you need tear-free animation, move to a Mega.
05

Or drive it from an ESP32

If the panel is the point of the project rather than one part of it, an ESP32 is the better host. ESP32-HUB75-MatrixPanel-I2S-DMA clocks the panel out over I²S with DMA, so the CPU never touches the refresh and you get far more colour depth than bit-banging allows. 

#include <ESP32-HUB75-MatrixPanel-I2S-DMA.h>

MatrixPanel_I2S_DMA *panel = nullptr;

void setup() {
  HUB75_I2S_CFG mxconfig(
    32,   // PANEL_RES_X
    16,   // PANEL_RES_Y
    1     // PANEL_CHAIN — one panel
  );

  panel = new MatrixPanel_I2S_DMA(mxconfig);
  panel->begin();
  panel->setBrightness8(90);       // 0-255; start low, it is bright
  panel->fillScreen(panel->color565(0, 0, 0));
  panel->setCursor(2, 4);
  panel->print("Hi");
}

void loop() {}

The library has a default GPIO assignment baked into its header — read it and pass your own into mxconfig.gpio if those pins clash with something. The ESP32’s 3.3 V outputs usually drive these panels fine; on long ribbons, a 74AHCT245 buffer between board and panel turns “usually” into “always”.

06

When it doesn’t light up

Nothing at all, or one dim garbled block
OE and LAT swapped, or you are plugged into the output header. Check the arrow on the silkscreen.
Image split or repeated vertically
An address line is wrong or floating. A, B and C must be A0, A1, A2 in that order.
Only the top or bottom half works
R1/G1/B1 and R2/G2/B2 are crossed, or one of the two triples is off by a pin.
Wrong colours, consistently
Two of the colour pins are swapped. The order across pins 1–7 is R1 G1 B1 · R2 G2 B2, with GND at pin 4.
Flicker, or the Arduino keeps resetting
The panel is drawing current through the Arduino. Separate 5 V supply, common ground.
Faint ghosting between rows
Normal at high brightness on cheap panels. Lower the brightness, or shorten the signal wires.
Sketch won’t compile: “no matching function”
You used the eight-argument constructor. A 32×16 panel has three address lines, so it takes seven.
